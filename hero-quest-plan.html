The Road Ahead — Development Phases
PHASE 0
Project Skeleton
A running app you can open in a browser with nothing broken
1–2 sessions
Deliverables
  • Next.js + TypeScript + App Router initialised
  • MUI installed with custom Skyrim-inspired theme
  • MUI theme provider configured for App Router
  • Supabase project connected, env vars set
  • GitHub repo + Vercel auto-deploy pipeline live
Learning Outcome
You will understand Next.js App Router project structure, the app/ directory, root layout, and how MUI theming works at the provider level.
PHASE 1
Auth & User Shell
A user can sign up, log in, and see a personalised shell — guests can browse without an account
2–3 sessions
Deliverables
  • Email/password sign-up and login via Supabase Auth
  • Guest mode (read-only) — factions, quest board, and story quests are publicly browsable without an account
  • Auth middleware — selectively protects personal routes only (profile, check-in, quest completion)
  • Persistent sign-in prompt for guests on interactive actions ("Sign in to track this quest")
  • User profile auto-created on first sign-in
  • Persistent app layout: nav, sidebar, content area
  • Placeholder user panel: avatar, level badge, XP bar (collapsed/login prompt for guests)
  • Sign out
Learning Outcome
You will understand Next.js middleware and selective route protection, Supabase Auth, the Server vs Client component distinction in a real auth context, and how to conditionally render UI based on session state.
PHASE 2
Quest Log Core
A user can create, view, and complete quests — the app feels usable
3–4 sessions
Deliverables
  • Quest creation form — title, type, description, faction
  • Quest list views per type, filterable
  • QuestCard — the core repeating UI unit, game-styled
  • Mark complete — XP gain, visual feedback
  • Fog quest quick-add (minimal friction, title only)
  • Lore-flavoured empty states per quest type
  • Basic XP accumulation saved to Supabase
Learning Outcome
You will understand Supabase CRUD, Next.js Server Actions for form submissions, component composition with MUI, and reusable component patterns.
PHASE 3
Factions
Factions feel alive and quests belong somewhere
2–3 sessions
Deliverables
  • Faction data seeded into Supabase (with named leaders — e.g. Corbin Guster Hammerfist)
  • Faction pages with lore, mascot, colour identity, leader character
  • Faction filtering on the quest log
  • Reputation system — XP per guild grows with completions
  • Rank titles (Apprentice → Journeyman → Master)
  • Faction colour bleeding into quest cards
  • Faction leader mood system — sidebar badge when quests neglected too long
Learning Outcome
You will understand Relational data in Supabase, dynamic routing in App Router (app/factions/[slug]/page.tsx), and contextual theming.
PHASE 4
Story Quests & Admin
Rich multi-step quests authored by you, experienced by users
2–3 sessions
Deliverables
  • Story quest detail page — checklist, progress bar, lore
  • Step completion tracked per user in Supabase
  • Admin route (your account only) for authoring quests
  • Quest Board view — available / in-progress / completed
  • Story quest cards visually elevated vs dailies
  • Random Quest Board — admin-curated pool of optional one-off quests ("learn a pen spinning trick", "text someone you haven't spoken to in a while")
  • Shuffle/deal mechanic — surface a random quest to the user on demand
Learning Outcome
You will understand Nested routing, role-based access with Supabase Row Level Security (RLS), more complex relational queries, and random/weighted data selection patterns.
PHASE 5
Gamification Layer
The rewards feel real enough to care about
2–3 sessions
Deliverables
  • XP thresholds, level-up animation & notification
  • Daily/weekly reset logic (midnight / Monday)
  • Streak tracking + streak freezes (max 2, replenishable via currency)
  • Daily Check-in — Fog prompt, reflection questions, optional streak-required dailies
  • Achievement scaffolding — define, detect, award
  • Quest difficulty tiers affecting XP reward
  • In-game reward shop — spend currency on UI themes, streak freezes, cosmetics
  • Full profile page — level, rep, streak, history
Learning Outcome
You will understand Cron jobs via Supabase Edge Functions or Vercel Cron, complex state management, and notification patterns.
PHASE 6
Polish & Feel
It feels like a game, not a to-do list in costume
Ongoing
Deliverables
  • Page transition & completion animations
  • Sound design (optional — completion, level-up)
  • Skyrim typography, iconography, decorative borders
  • Day/night mode (lore-flavoured dark/light)
  • Styled loading skeletons
  • Error & empty states written in lore voice
Learning Outcome
You will understand Animation libraries (Framer Motion), theming depth, accessibility considerations, and the craft of cohesive UI voice.

The Oracle — Ideas Under Consideration
These ideas have real promise but need more design thinking before they can be committed to a phase. They are recorded here so they are not lost to the fog.
🗺️ Paths Needs Design
Users naturally progress through themed "Paths" based on their faction reputation — no choice required. Example: reach Level 2 with the Fighters Guild and Level 3 with the Conclave to follow the Monk's Path. Paths could unlock cosmetics, titles, or unique quest lines.
Open questions: how many paths? Are they visible to the user before unlocked? Do they branch? Does path progress surface meaningfully in the UI or is it a background reward?
🃏 Community Quest Contributions Needs Design
Allow users to submit their own entries to the Random Quest Board — either freely or via a moderation queue.
Depends on social features. Needs a moderation strategy.
💬 Faction Leader Dialogue Needs Design
Leaders comment on your progress or neglect — extends the mood/badge system into something more narrative.
Could use pre-written dialogue lines triggered by reputation thresholds.
The Horizon — Mobile Migration Notes
Nothing to build yet. These are things to keep in mind as the web app is developed so the eventual React Native migration is smooth.

🔗

📦

🟦

The Creed — Guiding Principles
01
Frontend First
If a feature needs fake data to exist in the UI, that's fine. Wire it to the real backend once the component is solid.
02
Theme as Infrastructure
Every colour, spacing, and font decision lives in the MUI theme file — never hardcoded in a component.
03
Shared Components Early
QuestCard, FactionBadge, XPBar — built once, reused everywhere. This is how we make the UI easy to retheme later.
04
Nothing is a Black Box
We move at a pace where you understand every line. If something is introduced, it is explained.
